An educational AR scene with a physical interface

The team project turns nine printed markers into the Sun and eight planets. Looking at a marker reveals its associated 3D model, name and information. Users then rearrange the physical markers to place the planets in their expected order from the Sun.

The application combines classical computer vision, calibrated geometry and interactive graphics. The main engineering challenge is keeping camera images, marker poses, rendered models and game state consistent as markers move or disappear.

Course foundation: implementing the vision-to-scene pipeline

The earlier ar-exercise implementation contains the computer-vision work behind the application. A C++ CVCamera class is exposed to Godot through GDExtension, while a GDScript controller advances recorded camera frames, displays image-processing modes and updates marker-attached scene objects.

Thresholded images provide candidate contours. Polygon approximation, size limits and convexity tests select quadrilaterals. Edge-strip samples, line fitting and line intersections refine the corners before perspective normalization and rotation-aware binary marker decoding.

The pose stage uses known marker dimensions, four image corners and OpenCV solvePnP to construct a 4×4 rigid transform. The exercise converts the axes for Godot and exposes per-marker presence and transforms to GDScript. The demo attaches two scene objects to selected marker IDs and controls their visibility from the current detections.

Color, grayscale, threshold and diagnostic-overlay views make the stages inspectable, with an interactive threshold control. The local source also retains course solution references; this work is presented as a course exercise implementation and integration, with the course foundation credited.

My contribution

Architecture: camera geometry inside an interactive renderer

A native C++ CVCamera component exposes OpenCV capture and marker tracking through Godot’s GDExtension interface. The vision path thresholds the image, finds candidate quadrilaterals and refines their corners. It rectifies each candidate into a small grid, checks the black border and decodes the inner binary pattern across possible rotations.

Four image corners and the marker’s configured physical dimensions feed OpenCV solvePnP. Rotation and translation are converted into a homogeneous pose and then into Godot’s coordinate conventions. The scene maps each recognized ID to its planet model and updates the associated transform and labels.

Camera image dimensions and the projection field of view connect the video background to the virtual camera. The planet assets use adjusted visual scales and labels for an understandable tabletop experience.

Game logic, marker visibility and restart behavior

The ordering game uses the tracked planet transforms to compute distances from the Sun and sort the planets. The resulting order is compared with the expected sequence; label colors provide feedback and a completion state controls the success animation.

Marker loss and cached positions must be handled together with game state. My restart fix removes cached transforms at the beginning of a new round, while the start/exit/replay controls determine when completion checks are active. These changes support repeated interaction with the same physical marker set.

Inputs and assets

Inputs are live or replayed RGB camera frames, nine printed binary markers, and textured 3D planet meshes. The repository includes marker images, Godot scenes, planet assets and several recorded camera sequences for testing tracking and interaction.
