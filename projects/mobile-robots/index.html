A physical control problem

The course robot had to handle several different kinds of movement and interaction rather than follow one predetermined trajectory. The retained project contains line-following routines, obstacle-handling states, wall-distance calibration, box-pushing variants, and color-search logic. A differential drive provides locomotion, while an additional motor supports the task-specific mechanism.

This is a classical robotics and embedded-software project. It does not use a trained neural network or a benchmark image database. Its inputs are the robot’s live sensor readings, including reflected-light intensity, RGB color, gyroscope angle, ultrasonic distance, and touch events.

Mechanical design and sensor placement

My first course exercise connects mechanical choices to the course tasks: line tracking, obstacle handling, bridge traversal and color search. The sketches consider chassis stability, sensor placement and a mechanism for moving a box.

The retained BrickLink Studio archive contains five design versions, from 1.0 to 4.0. The original multi-view CAD studies below come from my personal exercise submission and show alternative robot and sensor arrangements.

Feedback and state transitions

Line tracking converts the difference between measured reflection and a calibrated threshold into a turning correction. The code contains proportional, integral, and derivative terms and experimental variants with different gains. The correction is applied as a difference between the left and right wheel speeds.

Sensor conditions select the next action. A touch event can interrupt tracking and enter an obstacle state, while a gyroscope-based heading check helps recover from a large deviation. Color-search routines classify RGB readings and use gyroscope feedback to maintain straight travel. Ultrasonic measurements are also used to relate commanded movement to physical distance.

My second exercise sketches a state machine for line following and recovery. Reflected-light categories select motion states such as straight travel, left or right correction, and reversal. The written transitions make the intended robot behavior explicit before implementation.

What the project emphasized

The main work was integrating sensing and control into repeatable on-robot behavior. Thresholds, wheel geometry, heading corrections, and transitions between behaviors all require physical calibration. The retained versions show iterative experiments with these choices rather than one universal controller configuration.

A state/context structure keeps line following separate from recovery and obstacle logic. This separation makes it easier to reason about a robot that must react to the environment while progressing through a larger task.
